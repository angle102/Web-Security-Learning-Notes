# 常用渗透测试工具总结

> 本文仅用于授权安全测试、靶场练习、CTF 学习和安全能力建设。
> 未经授权不得对真实网站、服务器、内网系统或第三方资产进行扫描、测试或漏洞验证。

---

## 一、工具学习目标

渗透测试工具不是为了“会点命令”，而是为了服务完整测试流程：

```text
信息收集
    ↓
资产发现
    ↓
端口扫描
    ↓
目录枚举
    ↓
漏洞扫描
    ↓
手工验证
    ↓
流量分析
    ↓
证据整理
    ↓
报告输出
```

常用工具包括：

```text
Burp Suite：Web 抓包、改包、重放、漏洞验证
Nmap：端口扫描、服务识别、基础漏洞探测
dirsearch：目录扫描、敏感路径发现
Nessus：漏洞扫描、资产风险评估
OpenVAS / Greenbone：开源漏洞扫描与基线检查
Wireshark：流量分析、协议分析、取证分析
```

学习重点不是单独记命令，而是理解：

```text
这个工具解决什么问题
在渗透测试哪个阶段使用
输入是什么
输出是什么
如何根据结果决定下一步
如何整理到报告中
```

# 二、工具在完整渗透流程中的位置

| 阶段     | 工具                  | 主要作用          |
| ------ | ------------------- | ------------- |
| 信息收集   | Nmap、dirsearch      | 端口、服务、路径发现    |
| Web 测试 | Burp Suite          | 抓包、改包、重放、验证漏洞 |
| 漏洞扫描   | Nessus、OpenVAS      | 自动化漏洞发现       |
| 流量分析   | Wireshark           | 协议分析、取证、文件提取  |
| 报告整理   | Markdown、Excel、截图工具 | 输出证据和修复建议     |

完整流程示例：

```text
Nmap 发现 80、443、8080 端口
        ↓
访问 Web 服务，Burp Suite 抓包
        ↓
dirsearch 发现 /admin、/api、/swagger
        ↓
Burp Suite 验证登录、越权、上传漏洞
        ↓
Nessus / OpenVAS 扫描主机漏洞和配置风险
        ↓
Wireshark 分析异常流量或靶场数据包
        ↓
整理漏洞复现步骤和报告
```

# 十二、面试表达模板

如果面试官问：“你平时怎么使用这些工具？”

可以回答：

```text
我会把工具放到完整渗透流程里使用，而不是孤立地使用某一个工具。

前期用 Nmap 做端口扫描和服务识别，用 dirsearch 做目录和敏感路径枚举；Web 测试阶段使用 Burp Suite 抓包、改包、重放请求，重点验证登录逻辑、越权、上传、SQL 注入和 XSS；资产漏洞评估阶段会使用 Nessus 或 OpenVAS 做自动化漏洞扫描，但扫描结果一定会人工复核；如果涉及流量分析、应急响应或 CTF 数据包，我会使用 Wireshark 过滤协议、追踪 TCP 流、导出 HTTP 对象并还原攻击过程。

同时，我会把工具输出结果整理成报告，包括资产清单、开放端口、敏感路径、漏洞复现步骤、风险等级和修复建议。为了提高效率，我也会写一些 Python 脚本处理扫描结果，例如 URL 存活检测、Nmap XML 解析、dirsearch 结果去重和报告表格生成。
```

# 三、总结

常用工具定位总结：

| 工具         | 核心作用        | 关键词           |
| ---------- | ----------- | ------------- |
| Burp Suite | Web 抓包与漏洞验证 | 抓包、改包、重放、越权   |
| Nmap       | 端口扫描与服务识别   | 端口、服务、版本      |
| dirsearch  | 目录扫描        | 后台、备份、接口、敏感文件 |
| Nessus     | 漏洞扫描        | CVE、配置风险、报告   |
| OpenVAS    | 开源漏洞扫描      | 漏洞发现、基线检查     |
| Wireshark  | 流量分析        | 协议、数据包、取证     |

一句话总结：

```text
工具只是手段，真正重要的是把工具结果转化为资产理解、漏洞判断、风险证明和修复建议。
```
