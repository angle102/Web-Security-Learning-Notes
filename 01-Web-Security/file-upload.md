# 文件上传漏洞复现笔记

> 本文仅用于授权安全测试、靶场练习、CTF 学习和代码审计学习。
> 未经授权不得对真实网站进行文件上传测试、绕过测试或漏洞利用。
> 本文所有测试思路应在本地靶场、DVWA、Pikachu、upload-labs、CTF 环境或授权项目中进行。

---

## 一、文件上传漏洞是什么

文件上传漏洞是指 Web 应用在提供上传功能时，没有对上传文件的类型、内容、路径、后缀、大小、权限等进行严格校验，导致攻击者可以上传非预期文件。

如果上传目录还能被 Web 服务器解析执行，就可能造成更严重的风险。

常见上传功能：

```text
头像上传
图片上传
附件上传
工单上传
简历上传
富文本编辑器上传
后台模板上传
Excel 导入
PDF 上传
压缩包上传
```

文件上传漏洞的核心问题是：

```text
用户上传的文件没有被安全地限制和隔离。
```

---

## 二、文件上传漏洞的危害

文件上传漏洞可能导致：

```text
上传恶意脚本
上传钓鱼页面
上传 HTML 造成 XSS
上传 SVG 造成 XSS
上传压缩包造成目录穿越
上传超大文件造成资源消耗
覆盖已有文件
上传敏感文件到公开目录
通过解析漏洞执行脚本
获取服务器权限
```

在真实项目中，最常见的风险不一定是直接拿到服务器权限，也可能是：

```text
用户隐私文件泄露
上传目录可遍历
任意文件覆盖
存储型 XSS
对象存储 Bucket 暴露
业务附件被越权访问
```

## 三、文件上传测试整体流程

文件上传测试可以按以下流程进行：

```text
1. 找上传点
2. 判断上传参数和返回路径
3. 测试前端限制
4. 测试后端后缀限制
5. 测试 MIME 校验
6. 测试文件头检测
7. 测试文件内容检测
8. 测试文件名处理
9. 测试上传目录是否可访问
10. 判断上传目录是否可执行
11. 判断是否存在解析漏洞
12. 判断是否存在越权访问
13. 总结风险并给出修复建议
```

## 五、前端校验与后端校验

### 5.1 前端校验

前端校验通常在 JavaScript 中完成，例如：

```javascript
if (!filename.endsWith(".jpg")) {
    alert("只允许上传 jpg 文件");
}
```

前端校验的特点：

```text
只在浏览器本地执行
可以被禁用
可以被 Burp Suite 修改请求绕过
不能作为真正的安全防护
```

判断方式：

```text
上传不允许的文件
抓包修改文件名
禁用 JavaScript
直接构造 HTTP 请求
```

结论：

```text
只靠前端限制文件类型是不安全的。
```

---

### 5.2 后端校验

后端校验在服务器端执行，才是真正有效的安全控制。

后端应该校验：

```text
文件后缀
MIME 类型
文件魔数
文件大小
文件名
文件内容
保存路径
访问权限
执行权限
```

但是如果后端校验不完整，仍然可能被绕过。

---

## 六、黑名单校验与绕过

黑名单是指禁止某些危险后缀，例如：

```text
php
jsp
asp
aspx
exe
sh
bat
```

示例逻辑：

```php
$deny = ["php", "jsp", "asp"];
$ext = pathinfo($_FILES["file"]["name"], PATHINFO_EXTENSION);

if (in_array($ext, $deny)) {
    die("禁止上传该类型文件");
}
```

### 6.1 黑名单的问题

黑名单的问题是：

```text
危险后缀可能列不全
大小写可能绕过
特殊后缀可能绕过
双后缀可能绕过
服务器解析规则可能和代码判断规则不同
```

---

### 6.2 大小写绕过

如果后端只拦截：

```text
.php
```

但没有统一转小写，可能出现：

```text
.PHP
.Php
.pHp
```

安全判断方式：

```text
后端应先将后缀统一转小写，再进行判断。
```

---

### 6.3 特殊可解析后缀绕过

某些服务器环境中，除了 `.php`，还可能解析其他后缀。

例如：

```text
.php3
.php4
.php5
.phtml
.jsp
jspx
.asp
.aspx
asa
cer
```

如果黑名单只写了 `.php`，就可能漏掉其他危险后缀。

注意：

```text
这些后缀是否能执行，取决于服务器配置。
测试时应在授权靶场中验证，不应在真实未授权目标上尝试。
```

---

### 6.4 双后缀绕过

常见文件名形式：

```text
test.php.jpg
test.jpg.php
test.asp;.jpg
```

风险取决于：

```text
后端如何取后缀
Web 服务器如何解析
是否存在解析漏洞
是否存在中间件特殊解析规则
```

如果后端只判断第一个点后的内容，或者只检查文件名中是否包含 `.jpg`，就可能产生绕过。

错误判断示例：

```php
if (strpos($filename, ".jpg") !== false) {
    echo "允许上传";
}
```

安全做法：

```text
只取最后一个后缀
统一小写
与白名单严格匹配
不要用 contains 判断
```

---

### 6.5 空格、点、特殊字符问题

某些系统或旧环境可能会处理文件名中的特殊字符：

```text
test.php.
test.php 
test.php::$DATA
```

风险取决于：

```text
操作系统
Web 服务器
语言框架
文件系统规则
```

安全做法：

```text
重命名文件
不要使用用户原始文件名保存
去除特殊字符
限制文件名字符集
```

---

### 6.6 黑名单总结

黑名单不推荐作为主要防护，因为它容易漏掉危险情况。

更安全的方式是：

```text
使用白名单。
```

---

## 七、白名单校验与绕过

白名单是指只允许明确安全的文件类型，例如：

```text
jpg
jpeg
png
gif
pdf
docx
xlsx
```

示例逻辑：

```php
$allow = ["jpg", "jpeg", "png", "gif"];
$ext = strtolower(pathinfo($_FILES["file"]["name"], PATHINFO_EXTENSION));

if (!in_array($ext, $allow)) {
    die("只允许上传图片文件");
}
```

### 7.1 白名单优势

白名单比黑名单更安全，因为：

```text
默认拒绝未知类型
只允许业务需要的类型
不需要枚举所有危险后缀
```

---

### 7.2 白名单仍可能出问题

即使使用白名单，也可能存在问题：

```text
只检查后缀，不检查文件内容
只检查 MIME，不检查文件魔数
文件保存到可执行目录
文件名可控
上传目录可解析脚本
允许 SVG、HTML 等主动内容
允许压缩包但不安全解压
```

---

### 7.3 伪造后缀

示例：

```text
真实内容是脚本或 HTML
文件名改成 test.jpg
```

如果后端只看后缀，就可能认为它是图片。

安全做法：

```text
后缀校验 + MIME 校验 + 文件魔数校验 + 内容重编码
```

---

### 7.4 图片重编码

对于图片上传，推荐做图片重编码。

例如：

```text
用户上传图片
服务端读取图片内容
重新生成一张新图片
保存重编码后的图片
```

这样可以去掉图片中可能夹带的异常内容。

常见处理方式：

```text
Java：ImageIO
PHP：imagecreatefromjpeg / imagepng
Python：Pillow
```

## 八、MIME 校验

### 8.1 MIME 是什么

MIME 类型用于表示文件内容类型。

上传图片时，HTTP 请求中可能出现：

```http
Content-Type: image/jpeg
```

常见 MIME：

```text
image/jpeg
image/png
image/gif
application/pdf
text/plain
application/octet-stream
```

在 multipart 上传中，每个文件字段也会有自己的 Content-Type，例如：

```http
Content-Disposition: form-data; name="file"; filename="test.jpg"
Content-Type: image/jpeg
```

---

### 8.2 MIME 校验的作用

服务端可能通过 MIME 判断文件类型：

```php
if ($_FILES["file"]["type"] != "image/jpeg") {
    die("只允许上传 JPG");
}
```

---

### 8.3 MIME 校验的问题

MIME 是客户端提交的，用户可以修改。

例如上传请求中：

```http
Content-Type: application/x-php
```

可以被改成：

```http
Content-Type: image/jpeg
```

所以：

```text
只依赖 MIME 校验是不安全的。
```

---

### 8.4 MIME 测试方法

在授权靶场中，可以使用 Burp Suite 抓包，观察上传请求。

重点看：

```text
filename
Content-Type
文件内容
服务端返回信息
```

测试思路：

```text
上传正常图片，记录请求格式
上传非图片文件，观察是否被拒绝
抓包修改 Content-Type 为 image/jpeg
观察是否绕过
```

判断结果：

```text
如果只改 MIME 就上传成功，说明后端可能只依赖 MIME 校验。
```

## 九、文件头检测

### 9.1 文件头是什么

文件头也叫文件魔数，是文件开头的固定特征。

常见文件头：

| 文件类型 | 文件头特征                               |
| ---- | ----------------------------------- |
| JPG  | `FF D8 FF`                          |
| PNG  | `89 50 4E 47`                       |
| GIF  | `47 49 46 38`，即 `GIF89a` 或 `GIF87a` |
| PDF  | `%PDF`                              |
| ZIP  | `50 4B 03 04`                       |

例如 GIF 文件开头通常是：

```text
GIF89a
```

---

### 9.2 文件头检测的作用

服务端可能读取文件前几个字节判断类型。

示例逻辑：

```text
读取文件前 4 个字节
判断是否符合 JPG / PNG / GIF 特征
```

这样比只检查后缀和 MIME 更可靠。

---

### 9.3 文件头检测可能存在的问题

如果服务端只检查前几个字节，而不真正解析图片，就可能被伪造文件头绕过。

例如文件开头是：

```text
GIF89a
```

后面却不是合法图片结构。

判断：

```text
如果服务端只看文件头，不解析完整文件，仍然可能存在风险。
```

---

### 9.4 正确的图片检测方式

更安全的做法：

```text
检查后缀白名单
检查 MIME
检查文件魔数
使用图片处理库真实解析图片
重新生成图片
保存重编码后的文件
```

判断是否为真实图片，而不是只看文件名前缀或文件头。

## 十、文件名处理问题

### 10.1 使用原始文件名的风险

危险写法：

```java
String filename = file.getOriginalFilename();
file.transferTo(new File("/upload/" + filename));
```

风险：

```text
路径穿越
覆盖已有文件
特殊字符绕过
文件名 XSS
文件名命令注入
文件名过长导致异常
```

例如：

```text
../../test.jpg
test"><script>alert(1)</script>.jpg
```

---

### 10.2 安全文件名策略

推荐：

```text
不要使用用户原始文件名作为存储名
使用 UUID 或随机文件名
后缀由服务端校验后重新拼接
限制文件名长度
只允许字母、数字、下划线、短横线
```

示例：

```text
原文件名：my photo.jpg
保存文件名：7f3a9c2e-8b1f-4e9b-9c1d.jpg
```

## 十一、上传路径问题

### 11.1 上传目录可访问

上传后需要判断：

```text
服务端是否返回文件路径
浏览器能否直接访问上传文件
上传目录是否可列目录
上传目录是否有执行权限
```

例如返回：

```json
{
  "url": "/uploads/2026/06/test.jpg"
}
```

访问：

```text
/uploads/2026/06/test.jpg
```

如果能访问，说明上传目录对外可访问。

---

### 11.2 上传目录可执行

上传目录可访问不一定危险，但如果上传目录可执行脚本，风险就很高。

例如：

```text
/uploads/test.php
```

如果服务器把它当作 PHP 执行，而不是作为普通文件下载，就存在严重风险。

安全做法：

```text
上传目录禁止执行脚本
上传目录放在 Web 根目录之外
通过后端接口读取文件
对象存储使用私有 Bucket
```

## 十二、解析漏洞

解析漏洞是指 Web 服务器、中间件或语言运行环境对文件的解析规则存在问题，导致本来不该执行的文件被当作脚本执行。

注意：

```text
解析漏洞强依赖具体环境和配置。
同一个文件名在不同服务器上结果可能完全不同。
```

---

### 12.1 Apache 解析相关问题

Apache 如果配置不当，可能根据多个后缀进行解析。

例如文件名：

```text
test.php.jpg
```

在某些错误配置下，可能被当作 PHP 处理。

风险原因：

```text
多后缀解析规则
AddType / AddHandler 配置不当
上传目录允许脚本解析
```

防护：

```text
上传目录关闭 PHP 解析
不要允许 .htaccess 覆盖配置
严格配置 AddHandler
上传目录只作为静态文件目录
```

---

### 12.2 Nginx + PHP-FPM 解析问题

Nginx 与 PHP-FPM 配置不当时，可能出现路径解析问题。

常见风险点：

```text
fastcgi 配置不当
PATH_INFO 处理不当
try_files 配置不严
图片路径后拼接脚本路径被错误解析
```

防护：

```text
正确配置 fastcgi_split_path_info
使用 try_files 限制真实 PHP 文件
禁止上传目录执行 PHP
限制 PHP 解释器只处理真实 .php 文件
```

安全配置思路：

```nginx
location ~ \.php$ {
    try_files $uri =404;
    fastcgi_pass 127.0.0.1:9000;
}
```

---

### 12.3 IIS 解析问题

旧版本 IIS 曾存在特殊解析问题，例如：

```text
目录名包含 .asp
分号解析问题
特殊后缀解析问题
```

风险常见于：

```text
IIS 6.0
老旧 ASP / ASP.NET 环境
历史遗留系统
```

防护：

```text
升级 IIS
关闭危险脚本映射
限制上传目录执行权限
禁用不必要的解析扩展
```

---

### 12.4 Tomcat / JSP 上传风险

Java Web 环境中，如果允许上传 JSP 到可执行 Web 目录，可能导致 JSP 被执行。

风险条件：

```text
允许上传 .jsp / .jspx
上传目录位于 Web 应用可访问路径
Tomcat 会解析该路径下 JSP
后端没有限制危险后缀
```

防护：

```text
禁止上传 JSP、jspx、class、jar、war 等文件
上传目录放到 Web 根目录外
通过文件下载接口访问附件
对上传内容进行类型检查
```

---

### 12.5 .htaccess 风险

在 Apache 环境中，如果上传目录允许 `.htaccess` 生效，攻击者可能通过配置改变解析规则。

风险条件：

```text
Apache 启用 AllowOverride
允许上传 .htaccess
上传目录可被配置覆盖
```

防护：

```text
禁止上传 .htaccess
关闭上传目录 AllowOverride
上传目录不允许脚本执行
```

## 十三、常见绕过点总结

| 绕过类型      | 示例思路             | 根本原因        |
| --------- | ---------------- | ----------- |
| 前端绕过      | 禁用 JS、抓包修改       | 只做前端校验      |
| MIME 绕过   | 修改 Content-Type  | 只信任客户端 MIME |
| 后缀大小写     | `.PHP`、`.Php`    | 没有统一小写      |
| 特殊后缀      | `.phtml`、`.php5` | 黑名单不完整      |
| 双后缀       | `.php.jpg`       | 后缀判断错误      |
| 文件头绕过     | 伪造 GIF/JPG 头     | 只检查前几个字节    |
| 文件名绕过     | 特殊字符、路径穿越        | 使用原始文件名     |
| 解析漏洞      | 上传目录被脚本解析        | Web 服务器配置不当 |
| .htaccess | 改变目录解析规则         | Apache 配置不当 |
| SVG/HTML  | 存储型 XSS          | 允许主动内容      |

## 十四、文件上传漏洞复现报告模板

```text
漏洞名称：文件上传漏洞

漏洞位置：
/upload

漏洞参数：
file

漏洞等级：
高危 / 中危 / 低危

漏洞描述：
目标系统在文件上传功能中，对上传文件的后缀、MIME、文件内容或保存路径校验不严格，导致用户可以上传非预期类型文件。若上传目录可执行脚本，则可能造成服务器权限风险；若上传 HTML/SVG，则可能造成存储型 XSS；若上传文件可被越权访问，则可能造成敏感文件泄露。

复现过程：
1. 访问上传功能，上传正常图片文件，确认上传接口和返回路径。
2. 尝试上传非允许类型文件，观察是否被前端或后端拦截。
3. 使用 Burp Suite 抓包，修改文件名、MIME 类型或文件内容，判断后端校验方式。
4. 判断服务端是否只检查后缀、只检查 MIME、只检查文件头或存在解析配置问题。
5. 上传后访问返回路径，判断文件是否可访问、是否可执行、是否存在越权访问风险。

影响分析：
攻击者可能上传恶意文件、伪造页面、触发存储型 XSS、覆盖文件、读取上传目录文件，严重情况下可能获得服务器权限。

修复建议：
使用白名单校验文件类型；校验文件魔数和真实内容；图片进行重编码；随机重命名文件；上传目录禁止执行权限；上传目录放到 Web 根目录外；限制文件大小；敏感文件使用鉴权下载；关闭危险解析配置。
```

## 十五、防护方案

### 15.1 使用白名单

只允许业务确实需要的类型，例如：

```text
jpg
jpeg
png
gif
pdf
docx
xlsx
```

不推荐只使用黑名单。

---

### 15.2 校验后缀

安全要点：

```text
统一转小写
只取最后一个后缀
严格匹配白名单
禁止双后缀误判
禁止特殊字符
```

---

### 15.3 校验 MIME

MIME 只能作为辅助判断，不能单独依赖。

建议：

```text
后缀校验 + MIME 校验 + 文件魔数校验 + 内容解析
```

---

### 15.4 校验文件魔数

读取文件头，判断文件类型是否符合预期。

但是文件头也可能被伪造，所以不能只依赖文件头。

---

### 15.5 图片重编码

对于图片上传，推荐：

```text
服务端真实解析图片
重新生成图片
保存重编码后的图片
丢弃原始上传内容
```

这样可以降低图片夹带异常内容的风险。

---

### 15.6 文件随机重命名

不要使用用户原始文件名保存。

推荐：

```text
UUID + 安全后缀
哈希文件名
日期目录 + 随机文件名
```

例如：

```text
/uploads/2026/06/7f3a9c2e8b1f4e9b.png
```

---

### 15.7 上传目录禁止执行

上传目录必须禁止脚本执行。

例如：

```text
PHP 不解析 upload 目录
JSP 不允许上传到 Web 根目录
Nginx/Apache 禁止上传目录执行脚本
对象存储不提供脚本执行能力
```

---

### 15.8 上传目录放到 Web 根目录外

推荐结构：

```text
/var/www/app
/data/upload
```

不要把文件直接保存到：

```text
/var/www/html/upload
```

更安全的访问方式：

```text
用户请求下载接口
后端鉴权
后端读取文件
后端返回文件流
```

---

### 15.9 限制文件大小

防止上传超大文件导致磁盘占满或服务异常。

建议：

```text
限制单文件大小
限制用户总容量
限制上传频率
限制压缩包解压大小
```

---

### 15.10 防止任意文件覆盖

不要允许用户控制完整保存路径。

错误做法：

```text
保存路径 = 上传目录 + 用户传入文件名
```

正确做法：

```text
保存路径 = 固定目录 + 服务端生成随机文件名
```

---

### 15.11 文件下载鉴权

上传文件如果包含隐私数据，不能直接公网访问。

应实现：

```text
登录校验
权限校验
资源归属校验
临时下载链接
短期有效签名 URL
```

---

### 15.12 对象存储安全

如果使用 OSS / S3 / COS / MinIO：

```text
Bucket 不应默认公开
使用临时凭证
限制上传类型
限制访问权限
设置防盗链
设置生命周期
敏感文件使用私有读
```

## 十六、代码审计关注点

代码审计时重点搜索：

```text
MultipartFile
getOriginalFilename
transferTo
FileOutputStream
Files.copy
upload
avatar
attachment
image
file
```

Java 危险写法：

```java
@PostMapping("/upload")
public String upload(MultipartFile file) throws IOException {
    String filename = file.getOriginalFilename();
    file.transferTo(new File("/var/www/upload/" + filename));
    return "success";
}
```

问题：

```text
直接使用原始文件名
没有后缀白名单
没有 MIME 校验
没有文件头校验
没有随机重命名
没有路径规范化
保存到 Web 可访问目录
没有限制执行权限
```

安全思路：

```text
获取原始文件名
提取最后一个后缀并转小写
判断后缀是否在白名单
读取文件头判断类型
使用图片库真实解析
生成随机文件名
保存到非 Web 根目录
数据库记录文件 ID 和真实路径
下载时进行权限校验
```

## 十八、总结

文件上传漏洞判断核心：

```text
上传的文件是否被严格限制
文件内容是否真实符合类型
文件名是否安全
保存路径是否安全
上传目录是否可访问
上传目录是否可执行
访问文件是否需要权限
```

测试重点：

```text
后缀
MIME
文件头
文件内容
文件名
保存路径
解析规则
访问权限
```

防护核心：

```text
白名单校验
文件真实类型检测
图片重编码
随机重命名
非 Web 目录存储
上传目录禁止执行
下载接口鉴权
数据库最小权限
对象存储私有化
```

一句话总结：

```text
文件上传安全的关键不是“能不能上传”，而是“上传什么、存到哪、如何访问、是否会被执行”。
```
